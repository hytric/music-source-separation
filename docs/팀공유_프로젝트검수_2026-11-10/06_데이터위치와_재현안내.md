# 데이터 위치와 재현 안내

## 1 실제로 찾은 위치

Windows·NAS 위치를 추적하기 위해 현재 문서와 주변 프로젝트 기록, 로컬 코드·데이터 저장소를 확인했다. **실제 사용 중인 코드와 음원은 Linux의 아래 경로에 있었다.** 이번 결과를 확인하는 데 Windows 또는 NAS 접속은 필요하지 않았다. 원래 11월 8일 OpenAIR 실험의 Windows/NAS 사본 위치는 확정하지 못했다.

아래 절대경로는 현재 작업 컴퓨터 기준이다. 팀원 PC에서 같은 경로가 자동으로 생기는 것은 아니다.

## 2 원자료와 공유 자료를 구분하기

이 팀 공유 폴더에는 원 음원·checkpoint를 복사하지 않았다. 표·설명·집계 CSV만 담았다. 실제 소스와 대용량 데이터는 기존 위치에 유지된다.

현재 프로젝트의 `.agent_reports/2026-11-10_review/evidence/`에는 검수 시점의 설정·manifest·개발/평가 JSON·실행 기록 사본과 SHA256 목록을 보관했다. `snapshot-index.json`이 원래 경로와 사본 해시를 연결한다. 팀 공유 문서의 숫자가 이후 다른 실행 기록과 섞이지 않도록 만든 사본이다.

기존 96개 문헌 카드와 조사 보고서는 코드 저장소의 다음 경로에 있다.

```text
.agent_reports/campaigns/2026-11-08_banelp-separation-poster-results/
2026-11-08_banelp-separation-survey/artifacts/
```

`cards/`는 개별 문헌, `report/`는 기존 종합 보고서다. 11월 9일 보충 조사는 `.agent_reports/notes/2026-11-09_supplementary-survey/`에 있다. 이 문서들의 당시 “C1 우선” 권고는 새 실험 결과보다 오래된 판단이다.

## 3 이번 검수에서 실제로 확인한 것

| 확인 | 결과 |
|---|---|
| 결과 JSON에서 40곡×4조건의 ΔSI-SDR 직접 재계산 | +1.652083117 dB, 기존 집계와 일치 |
| 곡 단위 10,000회 bootstrap 직접 재계산 | 95% CI [1.517792471, 2.000172273], 일치 |
| 곡별 평균 차이 Wilcoxon 재계산 | p=3.569388×10⁻⁸, 일치 |
| bass target gain <0.1 재집계 | 31→12, 일치 |
| 분할 manifest | 개발 10곡·평가 40곡, 중복 없는 목록 |
| 입력 stem 200개 | 파일 존재·크기·44.1 kHz·2채널·길이·manifest 일치 |
| 첫 곡의 4개 stem 전체 SHA256 | 모두 manifest와 일치 |
| 개발용 R1 표본 1개 | 혼합 `(2,N)`, 정답 `(4,2,N)`, 합 최대오차 약 5.96×10⁻⁸ |
| 실행 기록의 파일 해시 | 존재하는 기록 파일을 대조, 일치 |
| 선택 로직 테스트 | CPU에서 15개 통과 |

이 검수는 분리 모델의 재추론, 전체 음원 200개의 전수 해시, 모든 RIR 재생성, 실제 청취를 포함하지 않는다. 따라서 **저장 결과의 내부 일관성을 확인한 것**과 **모델 추론의 완전 독립 재현**을 구별한다.

## 4 안전하게 다시 확인하는 명령

다음 명령은 현재 컴퓨터에서 기존 상태를 읽는다.

```bash
cd /home/iiplab/code/music-source-separation
git rev-parse HEAD
git status --short

env PYTHONDONTWRITEBYTECODE=1 CUDA_VISIBLE_DEVICES= \
  OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 \
  .agent_runtime/banelp-v1/env/bin/python \
  -m unittest discover -s tests -p 'test_banelp_selection.py' -v
```

이번 별도 재집계 스크립트는 문서 프로젝트의 `.agent_reports/2026-11-10_review/audit_results.py`다. 입력은 evidence 사본과 기존 음원의 읽기이며, 출력은 이 공유 폴더의 CSV와 검수 JSON이다. GPU나 분리기 추론을 실행하지 않는다.

완료된 평가를 재생성하려고 `evaluation-40.claim`이나 선택 lock을 삭제하지 않는다. 새 조건 비교는 새 실험 버전·출력 경로로 설계한다. 과거 실행을 바이트 단위로 재현하려면 해당 코드·모델·config·환경·RIR·입력 해시를 먼저 함께 고정해야 한다.

## 5 추가로 확인할 원자료

11월 8일 원 실험과 정확히 비교하려면 원 `build_reverb_dataset.py`, `evaluate_separation.py`, `mask_probe*.py`, 원 10/40곡 목록, crop 위치, OpenAIR RIR 파일·채널·위치 ID, 원 점수표가 필요하다. 현재 확인한 패키지는 그 조건을 참고해 **다시 구성한 구현**이다.

현재 로컬 test 음원은 찾았지만 MUSDB train 전체와 원 OpenAIR 실험 세트의 위치는 이 검수에서 확정하지 않았다. 학습 실험을 시작하기 전에 train 자료 존재·이용 조건·validation 분할을 따로 확인한다.
