# 추가 잔향 영향 진단 사전 기록

사용자 지시: "일단 잔향이 문제인 포인트를 찾자. 원래 분리 - 잔향 데이터 분리 차이를 찾고 이를 분석"

범위: MUSDB18-HQ test 50곡의 기존 중앙 30초, 기존 개발10/평가40 구분 보존. HTDemucs 955717e8, FP32, shifts0, segment7s, overlap0.25, 공식 정규화. 새 학습 없음.

D0: 추가 RIR 없는 4 stem의 합을 분리하고 원 stem에 평가. 원 stem에 제작 잔향이 있을 수 있어 무향이라고 부르지 않음.
W1~W4: 기존 gpuRIR 혼합과 HTDemucs 출력 cache를 읽고 해당 wet 정답에 평가. 기존결과를 덮거나 다른방법을 선택하지 않음.
C1~C4: D0 분리 출력에 각 원 음원의 RIR과 데이터 생성에 쓴 동일 gain을 적용하여 wet 정답과 비교. 실제 사용 불가한 순서 대조/진단이며 새로운 후처리 성능이 아님. 출력 자체 RMS로 다시 정규화하지 않음.

지표: 기존 SI-SDR/SI-SIR/SI-SAR/SD-SDR/target gain, 각 정답의 각 출력에 대한 투영 계수(에너지 이동 비율 아님), 5초 구간, STFT 주파수대별 오차. 지표 구현은 기존 함수와 표본 동등성 대조. 같은 곡의 조건을 묶어 bootstrap.

주 비교: 곡·음원별 W-D0; 보조 비교 W-C(같은 wet 정답), 새 bass 소실, 조건별 악화. 이는 사용자 요청에 따른 별도 사후 진단이다. 이전 평가40곡을 다시 미관측 holdout으로 주장하지 않음. 후보·가중치 최적화 없음. 잔향시간과 DRR/스펙트럼 변화의 인과를 4개 조건만으로 확정하지 않음.

출력: 현재 cwd/잔향영향분석_2026-11-10/의 보고서·CSV·그림. 신규 dry 추정 cache는 /home/iiplab/code/music-source-separation/.agent_runtime/dry-wet-diagnostic-20261110/. 기존 코드·설정·결과·cache는 읽기 전용. 계산 전후 GPU 오류 확인, 오류 시 중단. CPU 2 threads 제한, GPU는 단일 HTDemucs만 사용.

실행 경로: 앞선 compose의 exFAT rename 실패는 기존 runtime_note.md에 기록됨. 자의적인 watcher/sleep 없이 도구의 foreground 실행과 결과 회수로 수행하며, 독립 worker 검증이나 runtime gate 완료는 주장하지 않음.

실행 보완: 원본 GPU 추론은 한 모델로 순차 수행한 뒤 종료한다. CPU 분석은 프로세스4개×BLAS2threads로 분할하며 각 프로세스가 동일 함수로 계산하고 결합한다. 1곡 pilot에서 기존 지표와 최대 1.84e-11 dB 차이, wet 정답 재합성 최대오차0 확인. 주파수대별 비교는 양쪽 정답의 해당 대역 에너지가 전체의1e-4 이상인 경우만 포함(약한 대역의 불안정한 비율 제외, 성능을 본 뒤 정한 기준 아님). 분석을 위한 모델 학습·후처리 변경 없음.
