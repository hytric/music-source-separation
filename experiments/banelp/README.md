# Banelp reproducible separation scaffold

This isolated research package uses the wet reverberant targets in `plan.md`'s contract and never imports or modifies the demo runtime. Its tensor order is `(vocals, drums, bass, other)`, stereo, 44.1 kHz, 1,323,000 samples. Dataset, cache, checkpoint, and environment payloads belong under `/home/iiplab/code/music-source-separation/.agent_runtime/banelp-v1`; artifacts contain compact manifests, hashes, and reports only.

## Environment

Provision Python 3.12 in the host research environment. Then run:

```bash
R=/home/iiplab/code/music-source-separation/.agent_runtime/banelp-v1
A=/home/iiplab/code/music-source-separation/.agent_reports/campaigns/2026-11-08_banelp-separation-poster-results/2026-11-08_autopilot-code-separation-claude-rout-400060999c/artifacts
bash experiments/banelp/bootstrap.sh --runtime-dir "$R" --artifact-dir "$A"
P="$R/env/bin/python"
"$P" -m experiments.banelp.cli validate --runtime-dir "$R" --artifact-dir "$A" --config experiments/banelp/config.json --synthetic
"$P" -m unittest discover -s tests -p 'test_banelp_*.py' -v
"$P" -m unittest discover -s tests -p 'test_runtime.py' -v
```

Bootstrap refuses a missing Python 3.12 interpreter and installs only into the runtime venv. `requirements.lock` pins direct dependencies; pip resolves transitives at install time, and the resulting exact environment must be captured in `evidence/environment.json` and the generated `requirements.resolved.lock` before claiming a fully reproducible environment. Package-index URLs are written in the script. Cache variables are redirected beneath the runtime directory.

## Dataset and model provenance

`prepare --track-root` validates an already acquired MUSDB18-HQ tree containing 50 directories with four stereo WAV stems named exactly `vocals.wav`, `drums.wav`, `bass.wav`, and `other.wav`. It records per-file SHA256, bytes, sample rate, channels, length, and a stable NFC/hash 10/40 split under `runtime/manifests/dataset.json`. It does not treat the free sample pack as HQ and does not silently omit short stems. RIR origin, channel selection, location, license, T30 and fallback details must be recorded in the host-run RIR manifest before wet targets are made. `data.apply_rir` applies the same selected mono response to both stereo channels, full convolution, N-sample truncation, then per-stem RMS restoration; no mixture peak normalization is done.

For each checkpoint retain model ID, URL/revision, file SHA256/bytes, explicit source order and training-data evidence. Training-data statuses: `verified-excluded` (with evidence), `documented-train-only`, `unknown`, `verified-included`. `documented-train-only` means the distribution table declares MUSDB18-HQ train (100 songs) only while no per-song audit exists; it needs `--declaration-url`, `--declaration-quote` and `--release`, is shown as "문서상 train-only, 곡별 감사 미확인", may be used as a candidate model, and is **not** `verified-excluded` (no clean-winner claim). Eligibility is always recomputed from status + evidence, never from a stored flag. `checkpoint_eligibility.json` lists the files that may be registered `documented-train-only` (MSST `docs/pretrained_models.md`, "Multi-stem models (MUSDB18HQ)": `model_bs_roformer_ep_17_sdr_9.6568.ckpt` v1.0.12, `scnet_checkpoint_musdb18.ckpt` v.1.0.6 (the tag literally has a dot), `SCNet-large_starrytong_fixed.ckpt` v1.0.9, `model_scnet_sdr_9.3244.ckpt` v1.0.8, `model_scnet_ep_54_sdr_9.8051.ckpt` v1.0.13; each entry also records the file's sha256/bytes, the release config file name + sha256 and both download URLs, and `register-model` refuses a different checkpoint or config hash for a listed file) and the excluded ones with reasons (`mdx_extra`, viperx BS-RoFormer ep_317, viperx Mel-RoFormer ep_3005, Kimberley MelBandRoformer); `register-model` refuses an excluded file or id. No architecture is accepted as a four-source checkpoint by name alone.

Which checkpoints matter is decided per dependency, never by "some model in the manifest is eligible": the sealed pipeline depends on the baseline plus the models of the selected candidate, and only those are checked (`policy.pipeline_dependencies`). A candidate model must be `verified-excluded` (with evidence) or `documented-train-only` (with declaration). The baseline htdemucs `955717e8` is not a clean winner: its training data is not verified per song (the paper split describes MUSDB18 test as unused, but the 800 extra songs were not audited per song). It opens the seal only through an explicit user decision record bound to that exact model in `selection.baseline_decisions` (`model_id`, `sha256`, optional `demucs_signature`, `decision`, `decided_by: user`, `date`) together with `baseline_train_data_policy: allow-unknown-with-disclosure`; a different id/sha or a missing record refuses, and `verified-included` always refuses. The Korean/English disclosure is written to the lock, `develop.json`, the seal and `results/evaluation.json`. Registering or removing an unrelated model changes neither the seal nor evaluate's acceptance (`models_manifest_hash` is recorded in `develop.json` for provenance only).

Demucs weights are loaded only from the registered, hash-verified files: `separators.load_registered_demucs` resolves what `get_model(name)` would load (remote `<name>.yaml` -> `files.txt` -> basenames; the sha256 must start with the hash in each file name), requires the registered members to equal that set exactly (count and names), and then loads exactly those files with `demucs.states.load_model` (`BagOfModels` for bags). MSST models load only from their registered config + checkpoint.

Demucs pre/post normalization follows the pinned 4.0.1 CLI (`separate.py:168-177`): `ref = wav.mean(0)`, centre and divide by `ref.std()`, `apply_model` (shifts 0, split, segment, overlap as configured), multiply by `ref.std()`, add `ref.mean()`. Baseline and donor re-separation both go through `separators.official_demucs_apply`. `std == 0` (silent/constant input; the official path would return NaN): the input is centred only (scale 1), restored with `+mean`, and `centered_only` is recorded (`separators.STD_ZERO_POLICY`). `smoke` runs the verbatim reference (`official_demucs_reference`) and the wrapper on the same CUDA input and records `official_path_parity.max_abs_diff`.

## Candidate boundaries

`candidates.py` exposes identity, T1 uniform mixture consistency, T2 estimated-PSD ratio masking (alpha configurable), T5 waveform blending, norbert Wiener, and a bounded C2 consistency iteration. The oracle function is separately marked and requires target tensors. Practical adapter entry points never accept target, RIR, or T60 arguments. All STFT paths use periodic Hann, 4096/1024, zero boundary, padded frames, spectrum scaling and stereo channel independence. Oracle namespaces are dev-only.

Metric configuration (`config.json` `metrics`) reaches the computation: `pinv_rcond`, `energy_epsilon` (a relative energy floor, `energy_epsilon x max(||s||^2, ||z||^2)`, for the finite dB display; both energies below it -> undefined, only the denominator -> positive infinity, a numerator below it is displayed at the floor and flagged `energy_floored`; original states and counts are kept) and `db_cap` (display cap). `center` other than `false` and any `stft` block that differs from `contracts.STFT_CONTRACT` (the constants `candidates.py` uses) are rejected by the validator. A silent target stays `silent-target` (absolute 1e-24).

Selection statistic (the approved plan's step 8): per dev (track, room) sample the mean dSI-SDR over the 4 stems; the effect, ranking and the +0.2 dB threshold use the **median over all dev track x room samples** (40 when complete). The 95 % CI is a percentile **track-cluster bootstrap** (B=10000, seed 20261108: tracks drawn with replacement, all rooms of a drawn track kept, the same sample-median recomputed); its lower bound must be > 0. SAR gate: for each stem the median dSI-SAR over all track x room samples must be >= `sar_floor_db` (-0.5); a stem with no defined sample fails. Wilcoxon (Holm family over the practical candidates, oracle excluded) uses per-track means; two-sided, `zero_method=wilcox`, `method=approx`, `correction=False`, all-zero -> p=1. `track_median_delta_db` / `track_bootstrap_95_ci` (median of per-track means) remain as non-gating report fields. The seal states the estimand and resampling unit in words (`statistic`). Rank: `-sample_median_delta_db`, additional inference calls, config hash; no eligible candidate -> identity.

Pre-registration: `lock-policy` writes `manifests/selection-policy.json` (+ artifact copy) **before develop**: adoption criteria (minimum gain, CI rule, SAR floor `-0.5` decided before any score was seen), statistic settings, the exact candidate set (name, params, config hash, models), the baseline id/sha256 and its eligibility decision. Its sha256 (of the canonical content) is stored with it. A lock with different content is never overwritten. `develop` refuses without a lock, with `sar_policy_status != confirmed`, or when the content recomputed from the current config/registry/models differs, and records `policy_lock_sha256`; `seal` requires equality with the lock file and with `develop.json` and embeds the lock content+hash; `evaluate` requires the same hash. Changing `minimum_sdr_gain_db`, `sar_floor_db`, the candidate set or a decision record after develop therefore refuses the seal. `selection.model_candidates` (e.g. `["replace:<model_id>", "average:<id>+<id>"]`, ids sorted) is the only place extra candidates are declared; the eval-spec fixes the list in the lock, it is not hard-coded. `replace:<id>` uses that model's estimates, `average:` an equal-weight waveform average; every depended-on model must be eligible. The `C-donor-*` candidates carry `evidence_status: exploratory` (no direct precedent for 4-stem frozen music separators; closest: speech OR-PIT, trained recursive models). `seal` never takes a hand-edited choice (`config.selection.selected` is rejected): it applies `selection.select_candidate` to the rows `develop` wrote and writes `selection-seal.json` (schema 4) binding the develop.json sha256, policy, lock, disclosure, depended-on models with status, dataset/RIR manifest hashes, code hash and lock hash. `evaluate` recomputes the same bindings through `provenance.verify_binding`, refuses any change, takes candidates from the same `candidate_registry` that `develop` used, and never chooses settings from evaluation outcomes. `develop.json` (schema 3) keeps every (track, room, stem) baseline/candidate/oracle observation with SI-SDR, SI-SIR, SI-SAR, target gain and the reason for each undefined value, plus per-candidate sample medians (overall and per stem) of the three deltas, the improvement ratio over the 160 pairs and undefined counts by reason.

MSST separators (BS-RoFormer, SCNet) use `separators.MSSTSeparator` on the official MSST code, pinned at tag **v1.0.23 = `f17924ddb1817cdbae6353706708c4518dd7cd14`** (`separators.MSST_PINNED_COMMIT`; checkout under `$R/src/MSST`, not in Git, must be clean and equal the registered `--msst-commit`). Its inference sequence is the official one: checkpoint through `utils.model_utils.load_start_checkpoint(args, model, ckpt, type_='inference')` after `torch.load(..., map_location='cpu', weights_only=False)` (strict; keys `state`/`state_dict`/`model_state_dict`; the file is hash-verified first); **FP32**: every release config sets `training.use_amp: true`, which would make `demix` run under fp16 autocast, so the adapter forces `config.training.use_amp = False` (original value and the forcing are recorded in the adapter attestation and the smoke file); **normalization** exactly as `inference.py:104-106,142-145`: only if `config.inference.normalize is True` (SCNet small and SCNet-large starrytong; not BS-RoFormer, SCNet large 9.3244, SCNet XL) the mixture goes through `normalize_audio` before and every estimate through `denormalize_audio` after `demix`; a silent/constant input (std 0, where `normalize_audio` would divide by zero) is centred only (std recorded as 1.0, `centered_only: true`). The model's chunked overlap-add `demix` then runs with the config's `num_overlap`; `config.inference.batch_size` is the config's value unless `register-model --msst-batch-size N` (recorded in the model record as `inference_overrides`) or, for one smoke only, `smoke --model <id> --msst-batch-size N` overrides it (eval-mode batching does not change results; tested). Output is reordered to the contract order. Register with `register-model --family msst --model-type <bs_roformer|scnet> --msst-config <yaml> --msst-commit <sha> --train-data-status documented-train-only --release <tag> --declaration-url ... --declaration-quote ...`. `smoke --model <model_id> --seconds 5|30` records peak allocated/reserved VRAM, RTF, finiteness and the adapter attestation; a model that cannot run in 6 GB is recorded as `excluded-cannot-run-in-6GB` with the error, never silently dropped (`reviews/smoke-<model>-<s>s.json`). The MSST inference dependencies (32 packages) are in `requirements.lock`, so the wet key hashes the real environment.

## gpuRIR fixed-layout RIRs

Since 2026-11-09 the primary RIR set is simulated, not downloaded: gpuRIR image-source method on the interim report's layout (`rir_geometry.json`: room 7.5 x 6.0 x 3.0 m, one omni microphone, four sources, all heights 1.5 m, fs 44,100, target T60 0.26/0.89/1.28/1.96 s for R1-R4). The simulation constants are those of the reference `rir_gen_gpuRIR.py` (`abs_weights` 0.9x5 + 0.5, diffuse model from 25 dB, end at 60 dB, c 343 m/s, LUT on, mixed precision off, one source x one receiver per call, no normalisation); `rir.load_geometry` refuses any deviation, including a T60 that is not the target. The Sabine absorption is not calibrated against the result: the T60 given to the simulator is the target (`t60_input_policy: "target (oracle); measured reported alongside"`), and measured EDT/T20/T30 are stored next to it. A short measured R1 is recorded, not regenerated.

`bash experiments/banelp/bootstrap_gpurir.sh --runtime-dir "$R" --artifact-dir "$A"` builds gpuRIR (pinned commit `06da27dd`, AGPL-3.0) with a CUDA 12.6 conda toolchain under `$R/gpurir-toolchain`, source under `$R/src/gpuRIR`, CMake arch patched to sm_75, and writes `build-record.json` (incl. the hash of the top-level `gpuRIR_bind` extension that pip installs next to the package, and its embedded `sm_targets`; the step fails without `sm_75`). Generation checks the RIR **onset** (first |h| >= 0.1 max|h|) against round(distance/c*fs) within +-8 samples, not the peak: with source and microphone at the same height the floor/ceiling reflections add coherently and can exceed the direct sound; `onset_index`, `peak_index` and `direct_delay_samples` are recorded per RIR. There is no CPU fallback; a failed build stops the run. The micromamba/conda-forge toolchain resolution is not fully pinned (package versions are resolved at build time); `build-record.json` (exact resolved packages, hashes, nvcc/driver versions) is the audit trail, not a lockfile. gpuRIR source and binaries stay in the runtime directory and are not redistributed; this repository holds only the script and the commit record. cuRAND makes the diffuse tail GPU/driver dependent, so the generated files are pinned by sha256 in `manifests/rirs.json`; regenerating produces a new manifest hash and a new wet cache key.

RT measurement (`data.decay_times`, recorded as `rt_method`): onset at the energy peak, 10 ms envelope, iterative noise-floor crosspoint (Lundeby-style), Schroeder integral cut at the crosspoint plus the extrapolated tail, ISO 3382-1 regressions (EDT 0 to -10 dB, T20 -5 to -25, T30 -5 to -35). A value that cannot be measured is `None` with a reason (`rir too short or silent`, `decay did not reach <x> dB`, `insufficient dynamic range above noise floor` when the noise floor is above -20/-35/-45 dB for EDT/T20/T30); nothing is guessed.

Archive of the previous (substitute RIR) condition, made by renaming in the runtime directory by the host-run: `rir-substitute-v1/`, `manifests/rirs-substitute-v1.json`, `cache/wet-substitute-v1/` (and `cache/separation-substitute-v1/` if present). The renamed manifest points at `rir/...` paths, so new code does not read it; read it with the `7b7f70a` checkout.

## Runtime commands

Host-run order: `prepare -> rirs -> build-wet -> register-model -> smoke -> lock-policy -> develop -> seal -> evaluate`. Every command takes `--runtime-dir "$R" --artifact-dir "$A" --config experiments/banelp/config.json`; `-h` on each shows its extra flags.

```bash
C="--runtime-dir $R --artifact-dir $A --config experiments/banelp/config.json"
"$P" -m experiments.banelp.cli prepare $C --track-root "$R/data/musdb18hq/test"        # manifests/dataset.json
"$P" -m experiments.banelp.cli rirs $C --gpurir experiments/banelp/rir_geometry.json \
    --gpurir-build-record "$R/gpurir-toolchain/build-record.json"                        # manifests/rirs.json (gpuRIR)
# legacy: rirs $C --sources rir_sources.json --synthetic-fallback (or --offline-synthetic)
"$P" -m experiments.banelp.cli build-wet $C                                              # cache/wet/<split>/<track>/R1..R4 + complete.json
"$P" -m experiments.banelp.cli register-model $C --model-id htdemucs --checkpoint "$TORCH_HOME/hub/checkpoints/<file>.th" \
    --introspect --train-data-status unknown                                             # manifests/models.json (baseline htdemucs: unverified, decision record in config)
"$P" -m experiments.banelp.cli smoke $C --device cuda --require-cuda --split dev --track-index 0 --seconds 5
"$P" -m experiments.banelp.cli lock-policy $C                                            # manifests/selection-policy.json (before any dev score)
"$P" -m experiments.banelp.cli develop $C                                                # results/develop.json (dev only)
"$P" -m experiments.banelp.cli seal $C                                                   # selection-seal.json
"$P" -m experiments.banelp.cli evaluate $C --seal "$A/selection-seal.json"               # results/evaluation.json, one claimed run
```

- `rirs --gpurir`: see the gpuRIR section; it cannot be combined with `--sources`, `--synthetic-fallback` or `--offline-synthetic`.
- `rirs` (legacy): `rir_sources.example.json` documents the source-list schema. Its URLs, checksums, licenses and archive members must be verified by the host-run (OpenAIR terms) before use. Each room tries its candidates in order (resumable download with checksum and disk-space check, safe archive extraction, native rate below 44.1 kHz rejected rather than upsampled); a room with no usable candidate uses the seeded synthetic RIR only when `--synthetic-fallback`/`--offline-synthetic` is given. The manifest keeps the target RT60 and the measured EDT/T20/T30 (or the failure reasons) separate, and records the native rate, extracted channel, resample method, hashes and license.
- `build-wet`: dry 30 s centre crop, full convolution with the manifest RIR (offset 0), keep the first N samples, per-stem RMS match to dry, float64 sum to a float32 mixture, no clipping. Entries are channels-first (`mixture (2,N)`, `targets (4,2,N)`) and `complete.json` is written last with the cache key and file hashes.
- `develop`, `smoke`, `seal`, `evaluate` and every cache reader (`data.read_cache_entry`) refuse a wet or separation entry without a matching `complete.json` (key, identity, file hashes); `develop`/`evaluate` regenerate a stale baseline-estimate entry from the practical mixture only. The wet cache key includes the code hash, so editing code requires `build-wet` again.
- `register-model` hashes every checkpoint file (bag members included) and records the native source order, sample rate and training-data status; `--introspect` loads the model with demucs and takes those facts from it. Checkpoints are loaded only after their registered sha256 is re-verified and matched against the member set `get_model` resolves (see above); `--introspect` loads those exact files, it does not rely on name resolution.
- Holdout claim: `evaluate` validates the seal bindings, every wet entry, every baseline estimate and the sealed candidate (preflight) before it writes `claims/evaluation-40.claim` as `started`; the claim becomes `completed` only after `results/evaluation.json` is written. Retry rule: a `started` claim for the same seal may be retried (an interrupted run persisted no holdout metrics); if results for that seal already exist the retry only finalizes the claim. A `completed` claim, or one bound to a different seal, is refused.

Dataset acquisition, RIR download, model cache creation, CUDA smoke and the full dev/evaluation runs belong to the registered host-run/lab stages. CUDA smoke fails closed instead of switching to CPU. Downstream cache keys use code, lock, source/crop/RIR manifest, synthesis, weights and inference configuration hashes. Oracle outputs use the independent `oracle-dev` namespace and never enter selection.
